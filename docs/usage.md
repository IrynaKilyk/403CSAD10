# Посібник користувача

## 1. Запуск агента

1. Відкрийте репозиторій у VS Code із розширенням GitHub Copilot.
2. Переконайтеся, що поточна гілка має формат `feature/...` і створена від `develop`.
3. У Copilot Chat виберіть режим **Agent**.
4. У корені репозиторію виконайте `/init`.

Команда `/init` послідовно запускає `/git-init`, `/create-project`, `/create-build`, `/create-actions` і `/check`. Вона зупиняється на першій помилці. Не запускайте її з гілок `master` або `develop`.

## 2. Окремі команди

Команди виконуються в Copilot Chat у режимі **Agent** з кореня репозиторію:

- `/git-init` — перевіряє Git-репозиторій, налаштовує `.gitignore` та `.gitattributes` без дублювання рядків і показує `git status`.
- `/create-project` — створює відсутню структуру мінімального Rust-проєкту `hello`: `Cargo.toml`, `src/main.rs`, `src/lib.rs`, а також каталоги `tests` і `docs`.
- `/create-build` — перевіряє або створює тест `BasicAddition` і CI-скрипти `ci.sh` та `ci.bat` для release-збірки, release-тестів і копіювання виконуваного файла в `build/`.
- `/create-actions` — перевіряє або створює `.github/workflows/ci.yml` для Ubuntu, Windows і macOS. Workflow використовує готові CI-скрипти.
- `/check` — лише перевіряє стан проєкту та нічого автоматично не виправляє.

## 3. Локальна перевірка

У корені репозиторію виконайте:

```text
cargo test
```

Для повної release-збірки, release-тестів і підготовки виконуваного файла використовуйте скрипт відповідної операційної системи:

- Linux/macOS:

  ```text
  bash ci.sh
  ```

- Windows:

  ```text
  ci.bat
  ```

## 4. Запуск зібраного проєкту

Після успішного виконання CI-скрипта запустіть файл із каталогу `build/`:

- Linux/macOS:

  ```text
  ./build/hello
  ```

- Windows:

  ```text
  .\build\hello.exe
  ```

Очікуваний вивід:

```text
Hello, World!
```

## 5. Перевірка командою `/check`

Команда `/check` виконує read-only перевірку та формує статус для кожного пункту:

- наявність і зміст конфігурації агента;
- наявність і структуру трьох skills;
- наявність шести commands;
- правильний порядок команд у `/init`;
- наявність `Cargo.toml`, файлів `src/`, тесту та CI-скриптів;
- успішне виконання `cargo build` і `cargo test`, зокрема тесту `BasicAddition`;
- успішне виконання `bash ci.sh` у Unix-подібному середовищі або `ci.bat` у Windows і наявність файла в `build/`;
- коректність GitHub Actions workflow, перелік трьох ОС, виклики CI-скриптів і відсутність зайвої логіки збірки та секретів;
- відсутність `target/` і `build/` серед відстежуваних Git-файлів та відсутність відомих шаблонів секретів у відстежуваних файлах.

У звіті кожен пункт має статус `PASS` або `FAIL`:

- `PASS` означає, що відповідна перевірка успішна.
- `FAIL` означає, що перевірка не пройдена; у звіті має бути коротко вказана причина.
- Перевірка продовжується після окремого `FAIL`, але загальний результат буде `FAIL`, якщо не пройшов хоча б один пункт.
- Успішним є лише звіт, у якому всі пункти мають `PASS` і в кінці зазначено `Загальний результат: PASS`.
